# Gamification System - Firestore Security Rules

## Overview
This document describes the security rules for the gamification system implemented in Training App V2. The rules ensure data integrity, privacy, and proper access control for the three main components: user progress, transactions, and settings.

## Collections & Security Model

### 1. `user_course_progress` Collection

**Purpose**: Stores each user's progress in a course (points, level, streak, etc.)

**Document ID Format**: `{userId}_{courseId}`

**Security Rules**:

| Operation | Who Can Access | Conditions |
|-----------|----------------|------------|
| **Read** | ✅ Owner (user) | Document ID contains their userId |
| | ✅ Trainer | Trainer of the course |
| | ❌ Others | Denied |
| **Create** | ✅ Enrolled user | Must be enrolled in course, creating their own document |
| | | Must set valid userId, courseId, and positive totalPoints |
| **Update** | ✅ Owner (user) | Via service only, userId/courseId cannot change |
| | | Points can only increase (no decrease) |
| | ❌ Manual edits | Denied |
| **Delete** | ✅ Trainer | For reset functionality |
| | ❌ Others | Denied |

**Helper Functions**:
```javascript
function getUserIdFromProgress() {
  return progressId.split('_')[0];
}

function getCourseIdFromProgress() {
  return progressId.split('_')[1];
}
```

**Example Document**:
```json
{
  "userId": "abc123",
  "courseId": "course456",
  "totalPoints": 350,
  "currentLevel": 5,
  "pointsToNextLevel": 50,
  "lastActivityAt": "2024-01-15T10:30:00Z",
  "dailyStreakCount": 7,
  "weeklyStreakCount": 2,
  "lastStreakCheckAt": "2024-01-15T00:00:00Z"
}
```

### 2. `points_transactions` Collection

**Purpose**: Immutable audit log of all point awards

**Document ID**: Auto-generated by Firestore

**Security Rules**:

| Operation | Who Can Access | Conditions |
|-----------|----------------|------------|
| **Read** | ✅ Owner (user) | Transaction belongs to them |
| | ✅ Trainer | Transaction is in their course |
| | ❌ Others | Denied |
| **Create** | ✅ User (via service) | Must be enrolled, creating their own transaction |
| | | Must have positive points value |
| | | Must include valid activityType and timestamp |
| **Update** | ❌ Everyone | Denied - transactions are immutable |
| **Delete** | ❌ Everyone | Denied - audit log must be preserved |

**Example Document**:
```json
{
  "userId": "abc123",
  "courseId": "course456",
  "activityType": "quiz_pass",
  "points": 50,
  "description": "Completed Quiz: Introduction to Flutter",
  "metadata": {
    "quizId": "quiz789",
    "score": 85
  },
  "timestamp": "2024-01-15T10:30:00Z"
}
```

**Activity Types**:
- `lesson_completion`
- `quiz_pass`
- `perfect_quiz`
- `assignment_submission`
- `module_completion`
- `wall_post` (if social enabled)
- `wall_comment` (if social enabled)
- `helpful_comment` (if social enabled)
- `reaction` (if social enabled)
- `daily_streak`
- `weekly_streak`

### 3. `courses` Collection - `gamificationSettings` Field

**Purpose**: Configurable point values and feature toggles per course

**Field Location**: `courses/{courseId}/gamificationSettings`

**Security Rules**:

| Operation | Who Can Access | Conditions |
|-----------|----------------|------------|
| **Read** | ✅ All enrolled users | Anyone in trainees array or trainer |
| | ❌ Others | Denied |
| **Update** | ✅ Trainer only | Must be course trainer |
| | | Other course fields must not change |
| | ❌ Trainees | Denied |

**Example Field Structure**:
```json
{
  "gamificationSettings": {
```

## Helper Functions

The following helper functions are defined globally and used across gamification rules:

### `isTrainerOfCourse(userId, courseId)`
Checks if a user is the trainer of a specific course.

```javascript
function isTrainerOfCourse(userId, courseId) {
  let course = get(/databases/$(database)/documents/courses/$(courseId));
  return userId == course.data.trainerId;
}
```

### `isEnrolledInCourse(userId, courseId)`
Checks if a user is enrolled in a course (either as trainee or trainer).

```javascript
function isEnrolledInCourse(userId, courseId) {
  let course = get(/databases/$(database)/documents/courses/$(courseId));
  return userId in course.data.trainees || userId == course.data.trainerId;
}
```

## Firestore Indexes

The following composite indexes are required for efficient queries:

### Index 1: Leaderboard Query
**Collection**: `user_course_progress`
```json
{
  "collectionGroup": "user_course_progress",
  "queryScope": "COLLECTION",
  "fields": [
    { "fieldPath": "courseId", "order": "ASCENDING" },
    { "fieldPath": "totalPoints", "order": "DESCENDING" }
  ]
}
```

**Use Case**: Get top 10 users in a course sorted by points
```dart
FirebaseFirestore.instance
  .collection('user_course_progress')
  .where('courseId', isEqualTo: courseId)
  .orderBy('totalPoints', descending: true)
  .limit(10);
```

---

### Index 2: User Transaction History
**Collection**: `points_transactions`
```json
{
  "collectionGroup": "points_transactions",
  "queryScope": "COLLECTION",
  "fields": [
    { "fieldPath": "userId", "order": "ASCENDING" },
    { "fieldPath": "courseId", "order": "ASCENDING" },
    { "fieldPath": "timestamp", "order": "DESCENDING" }
  ]
}
```

**Use Case**: Get user's transaction history for a specific course
```dart
FirebaseFirestore.instance
  .collection('points_transactions')
  .where('userId', isEqualTo: userId)
  .where('courseId', isEqualTo: courseId)
  .orderBy('timestamp', descending: true);
```

---

### Index 3: Course Transaction History
**Collection**: `points_transactions`
```json
{
  "collectionGroup": "points_transactions",
  "queryScope": "COLLECTION",
  "fields": [
    { "fieldPath": "courseId", "order": "ASCENDING" },
    { "fieldPath": "timestamp", "order": "DESCENDING" }
```

**Use Case**: Get all recent transactions for a course (trainer view)

```dart
FirebaseFirestore.instance
```

## Security Testing Checklist

Use the following checklist to validate security rules:

### User Course Progress
- [ ] ✅ User can read their own progress
- [ ] ❌ User cannot read other users' progress
- [ ] ✅ Trainer can read all progress in their course
- [ ] ✅ User can update their own progress (via service)
- [ ] ❌ User cannot manually decrease points
- [ ] ✅ Trainer can delete progress (for reset)
- [ ] ❌ Non-trainer cannot delete progress

### Points Transactions
- [ ] ✅ User can read their own transactions
- [ ] ❌ User cannot read other users' transactions
- [ ] ✅ Trainer can read all transactions for their course
- [ ] ✅ User can create transactions (via service)
- [ ] ❌ Transactions cannot be updated
- [ ] ❌ Transactions cannot be deleted

### Gamification Settings
- [ ] ✅ All enrolled users can read settings
- [ ] ✅ Only trainer can update settings
- [ ] ❌ Trainee cannot update settings
- [ ] ✅ Settings update doesn't affect other course fields
- [ ] ❌ Non-enrolled users cannot read settings

## Common Issues & Solutions

### Issue 1: "Permission Denied" when creating progress
**Cause**: User not enrolled in course
**Solution**: Ensure user is in `trainees` array or is the `trainerId` in course document

### Issue 2: "Missing or insufficient permissions" when updating settings
**Cause**: Non-trainer trying to update settings
**Solution**: Only trainers can update gamification settings

### Issue 3: Index not found error
**Cause**: Composite indexes not deployed
**Solution**: Run `firebase deploy --only firestore:indexes`

### Issue 4: Points decrease not working
**Cause**: Rule prevents points from decreasing (by design)
**Solution**: This is intentional for data integrity. Use trainer delete/reset instead.

---

## Best Practices

1. **Never bypass security rules**: Always use the service layer, not direct Firestore writes
2. **Test in emulator first**: Use Firebase Emulator Suite before deploying to production
3. **Monitor Firestore usage**: Check Firebase Console for any unexpected reads/writes
4. **Use transactions**: When updating progress + creating transaction, use Firestore transaction
5. **Validate on client**: Add client-side validation before attempting writes
6. **Log all point awards**: Every point award must create a transaction for audit trail
